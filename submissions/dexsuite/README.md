# DexSuite — Dexterous In-Hand & Pick-Place Manipulation Suite

**Robot platform:** [LEAP Hand](https://github.com/google-deepmind/mujoco_menagerie/tree/main/leap_hand) (16-DOF dexterous hand, MIT) on a custom **6-DOF actuated wrist** → 22 actuated DOF.
**Engine:** MuJoCo 3 · pure CPU · one-line install · fully headless.
**Built with:** Claude Code.

https://github.com/user-attachments/assets/demo — see [`demo.mp4`](demo.mp4) (generated by `python run.py record`).

---

## Task goal

A long-horizon tabletop **part-sorting** task that exercises the full dexterous-manipulation
stack end to end:

1. **Grasp** a red cube from its pick fixture with a multi-finger enveloping grasp.
2. **Reorient** the cube *in-hand* while held.
3. **Place** it in the colour-matched bin.
4. Repeat for a blue ball (different geometry → different contact behaviour).
5. **Press** a spring-loaded confirmation button with a single fingertip.

The autonomous policy completes **all 7 stages with a 1.00 success rate**, deterministically,
in ~28 s of simulated time. Every stage is verified by the simulator (lift height, in-bin
position, button travel) rather than asserted.

## Technical approach

- **Embodiment build.** The upstream LEAP `right_hand.xml` is re-parented under a 6-DOF
  wrist (3 prismatic + 3 revolute position actuators), giving Cartesian + orientation control
  of the palm without a full arm/IK stack. The hand is fully **sensorized**: fingertip
  **touch** sensors, a wrist **force/torque** sensor, a palm **IMU** (accelerometer + gyro),
  joint encoders, and a **wrist RGB-D camera**.
- **Grasp strategy.** The LEAP fingers flex *toward the palm*, so parts rest on slim
  **pick fixtures** at the hand's natural grasp-pocket height; the hand descends in a
  pre-shaped basket and closes into a stable envelope — robust to the knock-away that defeats
  naive top-down grasping. Tuned empirically against the model's contact physics.
- **Control.** A deterministic **state-machine planner** sequences interpolated (jerk-free)
  wrist moves and ramped finger closures. Carries are smooth so grasped objects are never
  flung; releases are slow so spheres settle into bins.
- **Closed-loop sensing.** Touch and force readings drive the live HUD and are logged for
  learning; grasp success is judged from physics state.

## Core features

| Mode | Command | What it does |
|------|---------|--------------|
| Autonomous | `python run.py autonomous` | Runs the task headless, prints per-stage pass/fail |
| Record | `python run.py record demo.mp4` | Renders the **annotated demo video** (HUD + wrist-cam inset) |
| Collect | `python run.py collect dataset 5` | Generates a randomized **imitation-learning dataset** |
| Teleop | `python run.py teleop` | **Keyboard teleoperation** in the MuJoCo viewer |
| Info | `python run.py info` | Prints model / sensor summary |

**Three control paradigms in one package** — scripted autonomy, human teleoperation, and
automated data collection — directly targeting the *Control* rubric dimension.

### Data-collection output
Each episode is a compressed `.npz` with synchronized streams: `finger_qpos` (16), `wrist_qpos`
(6), `touch` (4), `wrist_ft` (6), `imu` (6), `cube_pose`/`ball_pose` (7 each), `wrist_rgb`
(72×128×3), `action` (22), `time` — plus a `manifest.json` with per-episode success and the
domain-randomization seed. A 2-episode sample lives in [`dataset/sample/`](dataset/sample).

## How to run

```bash
python3 -m pip install -r requirements.txt   # mujoco, numpy, imageio, pillow, pyyaml
python run.py autonomous                      # verify the task (prints PASS/PASS/...)
python run.py record demo.mp4                 # regenerate the demo video
make test                                     # run the test suite
```
No GPU required. Tested with Python 3.11/3.13 and MuJoCo 3.9 on macOS (arm64) and Linux.
Tunable parameters live in [`config.yaml`](config.yaml).

## Current limitations

- Grasp acquisition relies on pick fixtures at hand height (a deliberate, realistic choice
  given the LEAP flexion geometry) rather than arbitrary top-down picking of free clutter.
- In-hand reorientation is wrist-led with finger bracing rather than full finger-gaiting.
- The planner is scripted/open-loop-timed; it uses sensors for verification, not yet for
  reactive replanning.

## Future improvements

- Tactile-reactive closed-loop grasping (close until touch thresholds, regrasp on slip).
- Learned in-hand reorientation policies trained on the generated dataset.
- Add an arm (e.g. Panda) under the wrist for unfixtured clutter picking.
