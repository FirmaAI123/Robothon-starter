# QuadLoco — Physics-Based Quadruped Locomotion

**Robot platform:** [Unitree Go2](https://github.com/google-deepmind/mujoco_menagerie/tree/main/unitree_go2) (12 torque-controlled joints, BSD-3).
**Engine:** MuJoCo 3 · real dynamics & contacts · CPU · one-line install · headless.
**Built with:** Claude Code.

See [`demo.mp4`](demo.mp4) — generated by `python run.py record`.

> **This is real physics, not animation.** Every frame advances `mj_step` with
> closed-loop **torque** control through ground contacts. (For contrast, the
> starter's quadruped example is a *kinematic puppet* — it writes `qpos` directly
> with `mj_forward`, no dynamics. A dedicated test, `test_is_real_physics`, proves
> ours responds to gravity.)

---

## Highlights

- **Genuinely dynamic locomotion** — 12 torque motors under PD control, every frame an
  `mj_step` through real ground contacts. A test proves it's physics, not animation.
- **Closed-loop IMU heading control** — sensor feedback cuts lateral drift **~2.5 m → 0.25 m**.
- **Terrain adaptation with no terrain sensing** — crosses a ramp + **procedural rough
  heightfield (±3 cm)** + a step, **20/20 trials upright**; robustness from the gait itself.
- **Quantified, not asserted** — randomized trials with 95 % Wilson CIs; deterministic; CI + tests.
- **Self-contained & reproducible** — one-line install, headless, no GPU, vendored model + license.

## Task goal

Make the Go2 **walk, traverse terrain, and steer** under full physics: an autonomous
**patrol** that crosses a **terrain course: gentle ramp → continuous rough heightfield (±3 cm) → low step**,
then steers through a **left/right turning sequence** with **closed-loop IMU heading-hold**,
driven entirely by motor torques reacting to the simulated dynamics.

## Results (quantitative)

Measured by `python run.py eval` — 20 randomized trials walking **over the terrain
course** (trunk mass ±12 %, initial heading ±0.05 rad, 10 s each), 95 % Wilson CIs:

| metric | result |
|---|---|
| stayed upright over terrain (no fall) | **20/20 = 100 %**  (95 % CI [84 %, 100 %]) |
| distance over terrain | **2.78 ± 0.46 m** |
| mean speed over terrain | **0.28 ± 0.05 m/s** |
| flat-ground walk (straight) | ~4.0 m, ~0.40 m/s |
| lateral drift (IMU heading-hold) | **0.25 ± 0.15 m** (vs ~2.5 m open-loop) |

Deterministic and reproducible (`test_determinism`).

## Method (technical detail)

QuadLoco is a complete legged-locomotion control stack — gait generation, joint-level
torque control, and a sensor feedback loop — running on the **full rigid-body dynamics**
of a 19-DOF floating-base quadruped (`nq=19`, `nu=12`) at a 2 ms (500 Hz) timestep.

**1 · Embodiment & sensing.** Vendored Unitree Go2 (12 motors: hip / thigh / calf × 4 legs;
torque limits ±23.7 / ±23.7 / ±45.43 N·m). Proprioception comes from a trunk **IMU**
(`framequat` orientation, `gyro`, `accelerometer`, `velocimeter`) plus **per-foot ground
contact** read from the MuJoCo contact buffer (foot-geom vs. floor).

**2 · CPG trot gait.** Each leg `i` runs a phase oscillator
`φ_i = 2π·f·t + Δ_i`, with diagonal pairing `Δ_FL = Δ_RR = 0`, `Δ_FR = Δ_RL = π` (a true
trot). Per leg the joint targets are

```
thigh*_i = θ0 + (sweep·v + turn·s_i)·cos(φ_i) + A_lift·max(0, sin φ_i)
calf*_i  = γ0 − A_calf·max(0, sin φ_i)
```

where `cos(φ)` drives the propulsive fore–aft sweep, `max(0,sin φ)` lifts the foot only
during swing for ground clearance, `s_i = ±1` is the leg's left/right sign (so a `turn`
term yaws the body), and `v` is the forward command. Tuned values: `f = 2.0 Hz`,
`θ0 = 0.9`, `γ0 = −1.8`, `sweep = 0.50`, `A_lift = 0.55`, `A_calf = 1.0`.

**3 · Joint torque control.** Every `mj_step`, all 12 motors are driven by PD torques
`τ = k_p (q* − q) − k_d q̇` (`k_p = 55`, `k_d = 2.2`), clipped to the motor force ranges —
so the robot is controlled purely through actuator torques reacting to contact forces, **never
by writing positions**. (`test_is_real_physics` asserts that with zero torque the trunk
sags under gravity — proof this is dynamics, not a kinematic puppet, unlike the starter's
quadruped example which sets `qpos` with `mj_forward`.)

**4 · Closed-loop IMU heading-hold.** Open-loop trotting drifts laterally (~2.5 m / 10 s
under randomization). We close the loop on the IMU: yaw `ψ` is read from the trunk
`framequat`, and on straight segments the steering command is a proportional correction
`turn = clip(k_ψ·(ψ − ψ*), ±0.15)` (`k_ψ = 2.5`) toward the anchored heading `ψ*` (re-anchored
through commanded turns). This **cuts drift from ~2.5 m to 0.25 ± 0.15 m** — a genuine
sensor feedback controller, not dead reckoning.

**5 · Terrain.** The same controller traverses a course with **no terrain feedback**: a
−0.12 rad ramp, a **continuous procedural rough heightfield** (60×120 grid, ±3 cm, smoothed
random elevation generated deterministically at load), and a 2.5 cm step — staying upright
in **20/20** randomized trials. Robustness emerges from gait + torque compliance, not sensing.

**6 · Autonomy.** A patrol scheduler sequences terrain-crossing → left turn → straight →
right turn → straight → halt, with heading-hold active on the straight legs.

## Core features

| Mode | Command | What it does |
|------|---------|--------------|
| Walk | `python run.py walk` | Headless autonomous patrol, prints distance/uprightness |
| Record | `python run.py record demo.mp4` | Renders the **annotated demo video** (live locomotion HUD) |

## How to run

```bash
python3 -m pip install -r requirements.txt
python run.py walk            # prints: traversed ~3.4 m, upright=True
python run.py eval 20         # reproduce the table above
python run.py record demo.mp4 # regenerate the demo video
pytest -q tests/              # 6 tests incl. real-physics & heading-hold checks
```
No GPU. Tested with Python 3.11/3.13, MuJoCo 3.9 (macOS arm64 / Linux).

## Current limitations & future work

- The gait clock is open-loop (no terrain *feedback* on foot placement), so very rough
  terrain or large external pushes would eventually trip it; heading is closed-loop (IMU),
  but foot placement is not.
- Next: contact-feedback foot placement for rougher terrain, slope/stair climbing, and a
  learned residual policy on top of the CPG.
