# QuadLoco — Physics-Based Quadruped Locomotion

**Robot platform:** [Unitree Go2](https://github.com/google-deepmind/mujoco_menagerie/tree/main/unitree_go2) (12 torque-controlled joints, BSD-3).
**Engine:** MuJoCo 3 · real dynamics & contacts · CPU · one-line install · headless.
**Built with:** Claude Code.

See [`demo.mp4`](demo.mp4) — generated by `python run.py record`.

> **This is real physics, not animation.** Every frame advances `mj_step` with
> closed-loop **torque** control through ground contacts. (For contrast, the
> starter's quadruped example is a *kinematic puppet* — it writes `qpos` directly
> with `mj_forward`, no dynamics. A dedicated test, `test_is_real_physics`, proves
> ours responds to gravity.)

---

## Task goal

Make the Go2 **walk, traverse terrain, and steer** under full physics: an autonomous
**patrol** that crosses a **terrain course: gentle ramp → continuous rough heightfield (±3 cm) → low step**,
then steers through a **left/right turning sequence** with **closed-loop IMU heading-hold**,
driven entirely by motor torques reacting to the simulated dynamics.

## Results (quantitative)

Measured by `python run.py eval` — 20 randomized trials walking **over the terrain
course** (trunk mass ±12 %, initial heading ±0.05 rad, 10 s each), 95 % Wilson CIs:

| metric | result |
|---|---|
| stayed upright over terrain (no fall) | **20/20 = 100 %**  (95 % CI [84 %, 100 %]) |
| distance over terrain | **2.78 ± 0.46 m** |
| mean speed over terrain | **0.28 ± 0.05 m/s** |
| flat-ground walk (straight) | ~4.0 m, ~0.40 m/s |
| lateral drift (IMU heading-hold) | **0.25 ± 0.15 m** (vs ~2.5 m open-loop) |

Deterministic and reproducible (`test_determinism`).

## Technical approach

- **Embodiment.** Vendored Go2 with 12 torque motors; a trunk **IMU** (orientation,
  gyro, accelerometer, body velocity) and **foot-contact** detection from the
  MuJoCo contact buffer provide proprioception.
- **Gait.** A **central-pattern-generator (CPG) trot**: diagonal leg pairs
  (FL+RR / FR+RL) swing in anti-phase; each thigh sweeps to propel the body and
  lifts during swing while the knee bends for ground clearance. A steering term
  biases left/right stride to **yaw**.
- **Control.** Joint targets are tracked by **PD torques** on all 12 motors, every
  `mj_step` — fully closed-loop on the simulated dynamics. Gains and gait shape were
  tuned empirically for a stable ~0.4 m/s walk.
- **Terrain.** The same open-loop gait traverses a ramp, a **continuous rough heightfield
  (±3 cm procedural terrain)**, and a low step with **no terrain sensing** — robustness comes from the gait itself (100 % upright over
  the course across randomized trials).
- **Closed-loop IMU heading-hold.** Straight segments steer with a proportional yaw
  correction from the trunk **IMU** to hold heading — closing the loop on the sensors
  cuts lateral drift from ~2.5 m to ~0.25 m. Not open-loop dead-reckoning.
- **Autonomy.** A patrol command schedule sequences terrain-crossing, left/right turns, and halt.

## Core features

| Mode | Command | What it does |
|------|---------|--------------|
| Walk | `python run.py walk` | Headless autonomous patrol, prints distance/uprightness |
| Record | `python run.py record demo.mp4` | Renders the **annotated demo video** (live locomotion HUD) |
| Eval | `python run.py eval 20` | **Quantitative** robustness eval with 95 % CIs |
| Info | `python run.py info` | Model / sensor summary |

## How to run

```bash
python3 -m pip install -r requirements.txt
python run.py walk            # prints: traversed ~3.4 m, upright=True
python run.py eval 20         # reproduce the table above
python run.py record demo.mp4 # regenerate the demo video
pytest -q tests/              # 6 tests incl. real-physics & heading-hold checks
```
No GPU. Tested with Python 3.11/3.13, MuJoCo 3.9 (macOS arm64 / Linux).

## Current limitations & future work

- The gait clock is open-loop (no terrain *feedback* on foot placement), so very rough
  terrain or large external pushes would eventually trip it; heading is closed-loop (IMU),
  but foot placement is not.
- Next: contact-feedback foot placement for rougher terrain, slope/stair climbing, and a
  learned residual policy on top of the CPG.
